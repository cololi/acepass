## 2. 四组剩余事项

### C01：结束练习的幂等重放仍泄漏评分（P1）

位置：`backend/apps/practice/api.py:205–213`。

普通练习正确提交并结束，得到 2 分；随后开启同题验证。当前 GET 旧会话已正确返回 `confirmed_score=null`、嵌套 `grade=null`，但以原幂等键重放 `/practice-sessions/{id}/finish`，仍返回 200、`confirmed_score="2.00"`、`is_correct=true`、`score_visible=true`。

原因是 `finish_session` 的重放分支仍直接返回 `replay.body`。这是 C01 所要求“所有结果交付与幂等重放应用当前门禁”的遗漏，不是要求新增一种门禁。

最小修复：重放同一个已结束会话，按当前权限重新执行安全序列化，保留结束操作的幂等性。回归同时覆盖验证开启隐藏、验证解除后恢复、结束副作用不重复。不能通过永远拒绝历史会话或永久清空评分来规避。

### C02：不同题干版本的分支仍能删除较新证据（P1）

位置：`backend/apps/analytics/services/reports.py:438–448`。

通过正常版本发布与重判服务构造：同题旧题干 qv1 的 gen1 任务排队；发布 qv2，完成 gen2 重判并生成 **6 条有效学习证据**；再执行 gen1。结果：新评分及 `applied_regrade_generation=2` 保留，但 6 条有效证据被清成 **0 条**，旧任务记录 `invalidated_evidence=6`、`stale_skipped_attempts=0`。

原因是“题干版本不同”直接批量失效证据，在进入 `regrade_attempt` 的代次检查之前就修改数据；随后只刷新考点状态，不恢复被删除的有效证据。这是顺序执行的数据错误，无须并发或计时条件。

最小修复：所有会修改评分或证据的分支都先锁定、刷新作答并检查代次；旧任务统一记为跳过，不得清除较新证据。保留新任务合理失效旧证据的正向行为。已修复的争议拒绝分支、序列方案和安全拒绝迁移继续保留。

### C04：HTTP 同步辅导绕过租约，导致同一任务内容分裂（P1）

位置：`backend/apps/tutoring/api.py:154`、`backend/apps/tutoring/tasks.py:69`、`backend/apps/tutoring/services/core.py:379–410`。

真实 HTTP 处理路径在 autocommit、`ACEPASS_INLINE_TASKS=False` 下仍执行 `run_tutor_job_now`，以 `claim=None` 进入业务写入。其 outbox 已提交为 pending，另一个消费者可以取得租约。

本轮通过确定性的 provider 回调交错，调用真实的 leased task：Worker 先完成并存储 `leased-worker-result`；迟到的 HTTP 调用再写入 `late-http-result`。最终 HTTP 和 `job.result_blocks` 为后者，助手消息却为前者；曝光 1 条、`finalized_at` 已有值、outbox 已 processed。**条数正确并不能证明内容一致。**

该测试使用 stub 模型和确定性交错，不冒充真实网络并发或真实模型证据；HTTP handler、数据库事务、claim 和 task 代码均为实际实现。

最小修复：生产 HTTP 与 Worker 统一取得并遵守同一任务的所有权。可保留受租约保护的同步路径，也可使生产 HTTP 入队后轮询；不能让存在 outbox 的请求以 `claim=None` 绕过保护。成功结果完成后应保持其内容与助手消息、曝光、审计一致；模型网络请求仍在短事务外。

新增反例允许正确的“HTTP 先持有租约，Worker 跳过”方案，不要求两个模型调用都发生。若改成异步，可调整测试驱动时序，保留最终业务一致性断言。

### C05：干净交付缺文件，验收脚本默认作用于既有项目（P1）

**可复现交付失败**：`.gitignore:3` 的 `.env.*` 使 `infra/docker/.env.example` 未被跟踪。在 `git archive HEAD` 导出的临时副本运行原全栈脚本，实际退出 1：`cp: infra/docker/.env.example: No such file or directory`。CI 的 `Compose config validation` 也在使用同一缺失文件。交付者本机全栈登录通过可以成立，但不能证明只靠提交能重现。

**未隔离行为**：`scripts/verify_proxy.sh:141–145` 在开始和退出时，对默认 Compose 项目执行 `down -v --remove-orphans`，随后直接覆盖 `infra/docker/.env`；Compose 默认项目名为 `acepass`。在已有同名部署的环境运行，可能删除既有数据卷。组件检查也使用固定资源名并预先删除同名容器。

安全 shim 在临时 fixture 中放入假配置哨兵，拦截全部 Docker 调用，证实删除卷命令及配置覆盖；没有为证明风险而真正删除任何部署。

最小修复：提交不含真实密钥的示例模板，保留真实配置忽略规则；检查脚本自行生成唯一测试项目、镜像标签和资源名，使用临时配置及媒体/证书路径，只清理本次创建的资源。不能依赖操作者记得手工设置项目名。验收覆盖空白 checkout、已有配置哨兵保持不变、正常退出与失败退出的资源隔离。
