## 2. 数据修复规则

1. 先修代码、新增回归，再处理历史投影。不能为了测试清空原库或重建真实用户数据。
2. 已保存原始作答、标准答案版本和旧 grade_event 保持不变；更正错误评分通过审计事件或可审计迁移处理。
3. `is_fully_confirmed` 改为“所有分项评分完成”；独立正确另要求确认分达到该题满分等条件。核对旧数据、报告分母及状态降级，不让语义更正意外把错题当正确。
4. 识别受 R03/R06 污染的验证证据：标记失效或待核查，不因代码修好便把历史验证自动视为干净。
5. 修复 B/C 任务时，依据真实最近事件重算未开始任务的锚点；保留原始时间与修订原因，不能悄悄提前到期。
6. outbox 的 pending/dispatched/processing/processed/failed 应有明确租约、attempt、next_retry_at 与最终失败状态。迁移旧 dispatched/failed 时先盘点已实际生效的业务，幂等重放；不能直接把所有行改 processed。
7. 在隔离库对存量样本 dry-run，输出影响数量与差异；需要在真实业务库执行时遵守当前用户授权范围，先提供可审查变更与备份恢复路径。

## 3. 验收必须扩大到这些分支

### 评分与一致性

- 单选/判断错答 0 分：已评完而非待评分；不会成为正确证据。
- 多选少选部分分：已评完，正式总分含部分分；不同项目规则独立。
- 大题 0/8/10 分，全部评分点已确认：全部为完成，待评分值均 0。
- 多空题只有一部分评分：保留确认分及真正待评的空位，不以失分估算待评分值。
- 先标争议后提交；人工评分页面过期；v2/v3 重判乱序；同 run 并发投递。

### 验证与延迟

- 网络层确认会话、报告、评分队列和证据接口不含活动验证正误/分数。
- 同题/已知家族/谱系在另一标签页或项目的练习、校对、文件与 tutor 请求不能绕过验证门禁。
- A 昨天、B 刚提交，C 必须从 B 或更晚相关学习事件起延迟；未来任务不能直接创建会话绕过。
- 从“开始验证”进入的 session.mode 必须为 verification，服务端不接受改为 practice 的降级请求。
- 使用可注入时钟测试 23:59/24:00 仅证明规则；真实隔天操作另列证据。

### 真实用户路径

使用全新验收账户，不加载已完成所有配置的演示数据作为唯一路径：

1. 创建两个项目、至少三个科目和各自规范；新科目无需刷新即可选中。
2. 粘贴题目并手工校对；实际上传单题图片，查看原图，补齐选项/空位/rubric/子题后发布。
3. 桌面和手机分别完成五种题型，不允许测试缺某类时 continue；断言每类真实分数或待评状态。
4. 提交大题照片及文本；刷新恢复；人工评分页核对原作答后给部分分。
5. 做错题后请求辅导，模型请求中包含本次答案和步骤；显示依据和候选诊断，不直接改掌握状态。
6. 完成即时 B、创建 C，通过真实 Worker 检查事件 processed、证据及任务落库；模拟到期再完成验证。
7. 从全局计划打开另一项目任务；报告按项目/科目显示正确数据；未结束验证不能泄露成绩。
8. 断开服务或使 API 返回 404/500，页面明确报错；不能将请求失败当空数据并使测试通过。

### 运维与模型

- 不使用内联消费者替代真实队列验收。所有实际生产事件主题都须有注册 consumer，增加 registry 合约测试。
- 在独立 Redis 中测试“已派发、未消费→队列丢失→数据库补发”；杀 Worker、异常重试、从备份恢复的结果也要核对。
- 确定一个 TLS 终止方案，统一 ALLOWED_HOSTS、内部健康探针、可信代理和 secure cookie；不要为过探针全局关闭生产 HTTPS。
- 从实际 Compose 数据库和媒体卷备份，在空库/空目录恢复。目标非空要在写入前拒绝；清单检查多余和缺失文件。
- 接通图片业务后才申请真实 provider 验收。Key 在本机环境中配置，不能写报告、日志或前端。
- 真实视觉和文本各至少一个人工核对样例，保存 provider/model/prompt/input version/用量和结果；模型无配置继续标未验证。

## 4. 回归资产与使用方式

[新增后端回归](review/2026-09-27/test_p0_regressions.py) 和 [新增 UI 回归](review/2026-09-27/ui-regressions.spec.ts) 是当前失败的规格测试，目的是固定现有问题；修复后应迁入正常测试目录并完善断言，不删除失败测试或改断言迎合错误实现。

后端可在仓库根目录运行：

```bash
PYTHONPATH="$PWD/backend:$PWD/docs/review/2026-09-27" \
  backend/.venv/bin/python -m pytest \
  docs/review/2026-09-27/test_p0_regressions.py \
  -c backend/pytest.ini --ds=review_settings -q
```

review_settings 指定独立的 `test_acepass_independent_regressions_20260927`，不使用真实业务库作为测试库。原 Playwright globalSetup 会 reset/rebuild 数据；运行前必须提供专用数据库、媒体、端口和缓存，禁止复用当前开发服务。浏览器隔离配置示例保存在证据目录，执行者应将隔离流程正式纳入 CI。

## 6. 修复验收后再做什么

1. **P1 第一批：真实内容与分析。** 在用户选定考试资料上做原生 PDF 批量导入、受控考点标签、完整周期覆盖与历年分值统计。前置条件是 P0 来源/答案/导入校对可靠。
2. **P1 第二批：复习和辅导增强。** FSRS 记忆卡、诊断追问、手写转写确认、AI rubric 估分；继续区分自评、估分和确定证据。
3. **按实际需要增加检索。** 题目与可信材料直接关联足够时，不为技术清单优先加入向量；数据量和检索评测说明需要后再做中文混合检索。
4. **P2 保持原计划。** 复杂扫描、可验证生成题、家族封存与限时模拟；不借修复之机提前扩大。

当前最有价值的下一步是让真实题目沿已有闭环正确运行，而不是增加页面或新模型能力。
