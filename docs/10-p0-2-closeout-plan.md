## 不可替代的验收场景

1. **事务与并发**：不要仅用 pytest 默认外层事务证明 HTTP 正确；使用 transaction=True 和两条实际数据库连接，含第一笔并发、已有历史后的并发及乱序执行。
2. **跨入口隔离**：活动验证留在标签页 A，标签页 B 对同题普通练习提交/请求辅导/读旧任务/看报告；检查原始响应，不只检查按钮或当前会话的 mode。
3. **延迟重算**：任务原本已到期，刚发生新训练或讲解后启动必须拒绝；B 打开很久但刚完成，C 不得被算隔天验证。
4. **真实异步竞争**：启动真正的消费者，在隔离 Redis 中实际清空待消费队列、终止占有租约的 Worker，再恢复；用两个消费者验证旧 token 和超时重投。每一步记录真实动作，不能只修改 DB 后命名为 kill/flush。
5. **用户输入保留**：大题照片→草稿已保存→刷新→照片还在→提交→人工评分页看到同一原图；图片导入→可视填空答案→保存→发布→答对获得正确分数；人工已校对时迟到模型结果不得改题。
6. **从空账户开始**：仅创建登录账户，经 UI 新建两项目/多科目、规范、上传/校对/发布题目、作答、评分和复习。不得预先用 bootstrap 填好所有业务内容再称 UI 全流程通过。
7. **CI 与恢复**：运行实际 workflow 对应命令；不能只 --list。故意不可连数据库的恢复 dry-run 必须失败，正常空库恢复必须通过，端口跳转到真实可登录入口。
