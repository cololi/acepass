# AcePass 验收规格

这是验收清单本体。§2 的 A01—A42 已在 P0/P0.1/P0.2 各轮实际执行并留证（见 `docs/08`—`docs/15`
与 `docs/acceptance-results.md`）；§3 的 B/C 条目按 [17 计划](17-remaining-plan-to-completion.md)
分批次执行，未执行的条目标为"批次 N / 未验证"，不会被写成通过。业务正确、真实 AI 接入、
长期学习效果是三类不同证据。

## 1. 夹具与测试环境

准备两个用户（一个普通 owner、一个用于越权测试的独立用户），另按需要建立内部 staff。普通 owner 创建 A/B 两个项目，项目 A 至少两个科目。使用不同大纲和多选计分规则；同文题分别导入 A/B 验证隔离。

至少 30 个可评分叶子题，单选、多选、判断、填空、大题每类至少 4 道；另加父材料、图片、跨区域来源、答案页与疑点图片。含 3 道针对同一知识点的 A/B/C 配对练习、两种模板、近重复家族和封存候选。固定正确答案、分值、评分点、期望判分、来源区域和审核人。

金标由人工独立核对，不由待评模型生成后自称标准答案。演示题不计入真实历年统计。两项目规则例：某多选题满分 4，正确集合 `{a,c}`；A 采用少选得 2 分，B 采用完全匹配。提交 `{a}` 在 A 得 2，在 B 得 0。

后端关键测试使用 PostgreSQL 的真实约束与事务；时钟可注入以测试边界。模型接口使用可控 stub 验证失败、输出和权限；另设 real-provider 测试，不将两者混为成功证据。

## 2. P0 必过用例

| ID | Given / When | Then：验收结果 |
|---|---|---|
| A01 | 空数据库启动并执行迁移、创建账户、登录 | 可以进入空项目页；步骤可复制，无人工改库 |
| A02 | 未登录请求业务/文件；跨站提交无 CSRF | 分别拒绝访问/写入；登录和退出也校验 CSRF，无敏感响应 |
| A03 | A/B 不同题库与规则，切换 B 后答题；伪造路径/外键 | B 的界面、评分、任务和报告正确；A 状态不变；混用资源返回 404/业务校验错误 |
| A04 | 另一个用户访问已知项目/文件/job/attempt ID | 所有入口拒绝，后台任务和缓存不泄露原用户内容 |
| A05 | 已发布题干、答案、规范被修改 | 只能创建新版本；旧 attempt/session_item 仍指向原版本 |
| A06 | 粘贴含负号、单位、选项的题目 | 原文可追溯，结构可编辑；不是仅保留识别后文本 |
| A07 | 模糊图片、少选项、缺图、答案题号冲突 | 停在 awaiting_review；不发布、不猜答案、不进入计分任务 |
| A08 | 同文件重试、同卷另存图片后重导入 | 候选可人工确认重复；真实 paper_item 数量不翻倍 |
| A09 | 发布时题型字段缺失、答案 pending/disputed、rubric 不一致 | 发布失败并指向问题；修正后才可发布 |
| A10 | 单选选项重排，多选不同顺序；判断提交 false | 按稳定 ID/布尔值判分；false 不当漏答，多选集合不受顺序影响 |
| A11 | 上述多选 `{a}` 分别提交项目 A/B；提交 `{a,b}` | A=2、B=0；错选按各自 wrong_score；规则版本保存在题项/判分 |
| A12 | 填空规则显式允许大小写/空白处理；`-2` 与 `2` | 只做配置允许的规范化；负号不能丢失，原始输入保留 |
| A13 | 材料父题带两个 3/7 分子题；10 分题考点权重 0.6/0.4 | 试卷计 10 分；考点计 6/4，父题不再计分；权重不合法拒绝发布 |
| A14 | 同一题在两个真实年度出现；同年同卷被重复上传 | 年度发生记录保留两次；重复上传不增加第三次 |
| A15 | 数值标准 10，abs_tol=0.1、rel_tol=0；提交 10.1/10.11 | Decimal 边界分别通过/按明确规则判错；未知单位或解析失败待复核 |
| A16 | 填空提交未登记等价式；两空中一空可判、一空待复核 | 不直接判错或记总分 0；显示确认分/待评分值；不进入完整正确率 |
| A17 | 大题 rubric 三项 2/3/5 分，给分 2/2/4 | 确认总分 8；超上限、漏必填项拒绝；显示自评/复核来源与理由 |
| A18 | 大题上传照片后提交；尚未实现手写识别 | 原图能查看，原始附件不可被后续替换；不伪造识别步骤；未评分保持待评 |
| A19 | 提交前另一标签页查看提示/解析，再在本页答对 | 记录辅助作答，不能产生严格独立证据；跨会话记录有效 |
| A20 | 独立提交后才 reveal 答案来自评 | 提交前暴露标志不被倒改；评分来源为 self_confirmed，严格证据仍排除自评 |
| A21 | 同一幂等键并发提交 5 次；之后同键不同答案 | 只有一个 attempt/初判效果；同载荷返回同一结果；不同载荷 409 |
| A22 | 新答案重判先完成、旧任务后返回 | 原作答和旧事件保留；有效指针指向指定新 revision；计数只消费一次当前结果 |
| A23 | 编辑已使用规范、大纲或答案后继续旧会话 | 不混配最新版；出现争议则保留提交并转待复核；兼容修正走明确重判 |
| A24 | 导入工人崩溃后任务重复投递，发布请求重试 | 来源/候选/版本不重复；任务可恢复；业务状态来自数据库 |
| A25 | 同一题重复、改题版本、换数近重复题多次答对 | 不能伪装成不同题/陌生模板的多条独立证据；显示重复/家族限制 |
| A26 | 验证模式调用 tutor/reveal/编辑 API；取整页答案图或缓存解析 | 服务端拒绝或先结束验证并记录污染；题干响应、调试字段、文件资源不泄露答案 |
| A27 | 手机/桌面分别完成全部题型，刷新和多标签修改草稿 | 输入完整、图片/公式可读；草稿恢复；旧 revision 覆盖返回冲突 |
| A28 | 模型超时/无密钥/非法 JSON/伪造引用 | 作答与确定性判分继续；辅导明确失败/未配置；重试有上限，坏结果不入正式内容 |
| A29 | A/B 项目共享 60 分钟预算，多个到期大题超量 | 今日计划预计总量不超过 60；保留未开始任务并顺延；展示理由和积压，不复制任务 |
| A30 | 延迟阈值 24h；在 23:59h/24:00h 开始合格验证 | 边界前不算延迟、达到后可算；中间相关讲解更新锚点；UTC 判定不受时区/夏令时误差影响 |
| A31 | 原题讲解后完成 B，再到期完成 C | 区分即时配对/延迟证据；缺 C 或 C 已见答案时明确降为重复练习，无虚假掌握 |
| A32 | 只有错误选项没有过程，或用户否认诊断 | 原因可保持 unknown/proposed，不能强认粗心；诊断不直接改成绩或掌握 |
| A33 | 正式分、部分待评、自评、AI 模拟估分混合 | 报告分别展示；AI 估分不能进入正式总分；样本分母和排除原因明确 |
| A34 | 同题不同用户/项目/作答要求个性化辅导；撤回后读缓存 | 个人内容不串用；撤回/用途策略即时生效；AI 无 DB 写工具，恶意题干指令不能改变评分 |
| A35 | 数据库和媒体备份后在空位置恢复 | 原始作答、版本引用、来源裁图可读取；Redis 丢失可重建任务，不丢原始事实 |
| A36 | 配置真实视觉/文本 provider 执行一次导入和讲解 | 保存模型/提示版本和用量；人工确认实际内容；无凭据则明确“未验证”，不以 stub 替代 |
| A37 | 已配对练习尚未提交便请求提示/完整讲解或答案，再多次读取、提交和重判 | tutor 绑定 session_item、不要求 attempt；可展示并记辅助暴露；后续答对不得算严格独立；讲解/评分只触发一个 B，B 复评分也不重复建 C |
| A38 | 创建含三题的验证会话，逐题领取并提交判断题 | 未领取题无呈现时间；恢复不重置；整个验证结束前提交/查询/报告均无正误或分数反馈 |
| A39 | 打开大题自评页后发生答案重判，再提交旧页面；管理员为自己打分 | 旧评分 revision 返回 409；管理员本人仍 self_confirmed，不能伪装 reviewer_confirmed |
| A40 | 单题无 paper_item，规范默认 2 分；材料父题无答案；配对任务重复触发 | 发布固定练习分值 2；材料可整组发布且只给叶子建提交题项；相同触发只建一个 B/C 任务 |
| A41 | 将已看答案的题复制至本人另一项目并标成“新题” | 已知内容谱系识别既往暴露，不能恢复首次资格；两项目分数和状态仍分别保存 |
| A42 | 两项目等比例只有 2 分钟预算，两者最短题均 2 分钟；次日重算、同日重试 | 共享余额按日期轮换给能容纳整题的项目；次日公平轮换，同日重试确定，预算不跨日透支 |

A30 的可注入时钟测试是调度正确性证据；真实用户隔天作答必须实际经过时间后另记。A36 是依赖真实服务的集成项；未完成时可交付已完成工程，但不得写“全部 P0 AI 验收通过”。

额外检查：非法选项 ID、同一多选 ID 重复、过大图片、伪造 MIME、路径穿越、未授权附件绑定、HTML/脚本注入、撤回题和归档项目。这些检查覆盖在相应单元/API 测试，不只靠手动点击。

## 4. AI 回归与证据报告格式

更换 provider、模型或提示词版本后，在同一人工集回归：题干/选项/负号/单位准确性、答案题号匹配、来源定位、讲解与评分标准一致性、诊断不确定性和权限过滤。按题型报告数量及错误案例，不只给平均分。

初始硬性发布门槛是“疑点不能绕过人审、权限零越界、确定性评分金标完全符合规则”；不预先承诺 OCR 达到 99% 或某模型能提升多少分。真实模型输出质量不佳可以继续手工路径，但需保留失败原因。

实现后生成 `docs/acceptance-results.md`，每项记录：用例 ID、代码/配置版本、自动化或人工、真实或 stub、实际命令/步骤、预期/实际、证据路径、通过/失败/未运行及原因。CI 通过不替代真实浏览器和 provider 验收；浏览器正常不等于真题学习效果已验证。

## 5. 交付完成判据

- 所有题型和多项目核心流程可实际操作，没有仅静态展示的核心页面。
- 数据库迁移、依赖锁文件、启动/测试/备份/恢复命令齐全且实际运行记录可查。
- P0 业务、安全与一致性测试通过，真实 AI 验收的通过或缺项如实说明。
- UI 不展示未经计算的统计、伪造学习进度或把自评/估分当确定性证据。
- P1/P2 未交付功能与真实延迟/长期效果未验证事项明确列出。
